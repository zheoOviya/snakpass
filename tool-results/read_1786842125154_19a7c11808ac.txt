   300→```ts
   301→// Hypothetical getCachedResponse with C1 (NOT in 3c Gate Review scope)
   302→export async function getCachedResponse(
   303→  tx: Prisma.TransactionClient,
   304→  key: string,
   305→  incomingRequestHash?: string,  // NEW parameter — computed by caller, outside txn
   306→): Promise<{ status: number; body: string } | null> {
   307→  const record = await tx.idempotencyKey.findUnique({ where: { key } })
   308→  if (!record) return null
   309→  if (record.expiresAt.getTime() < Date.now()) return null  // TTL check (unchanged)
   310→
   311→  // C1: requestHash enforcement (gated by feature flag)
   312→  if (incomingRequestHash && record.requestHash && isFeatureEnabled('requestHashEnforcement')) {
   313→    if (record.requestHash !== incomingRequestHash) {
   314→      throw new IdempotencyKeyReuseError({
   315→        idempotencyKey: key,
   316→        resourceType: record.resourceType,
   317→        storedResourceId: record.resourceId,
   318→        storedRequestHash: record.requestHash,
   319→        receivedRequestHash: incomingRequestHash,
   320→      })
   321→    }
   322→  }
   323→
   324→  return { status: record.responseStatus, body: record.responseBody }
   325→}
   326→
   327→// Hypothetical storeIdempotencyRecord with C1 (NOT in 3c Gate Review scope)
   328→export async function storeIdempotencyRecord(
   329→  tx: Prisma.TransactionClient,
   330→  key: string,
   331→  resourceType: string,
   332→  resourceId: string,
   333→  responseStatus: number,
   334→  responseBody: string,
   335→  requestHash?: string,  // NEW parameter — computed by caller, outside txn
   336→): Promise<void> {
   337→  const expiresAt = new Date(Date.now() + IDEMPOTENCY_KEY_TTL_HOURS * 60 * 60 * 1000)
   338→  await tx.idempotencyKey.create({
   339→    data: {
   340→      key,
   341→      resourceType,
   342→      resourceId,
   343→      responseStatus,
   344→      responseBody,
   345→      expiresAt,
   346→      requestHash: requestHash ?? null,  // null for pre-3c callers (defensive)
   347→    },
   348→  })
   349→}
   350→```
   351→
   352→The new `IdempotencyKeyReuseError` class would be caught by the route handler (in both `orders/route.ts` and `payments/route.ts`) and translated to HTTP 422 with the response shape from §3.3.

   574→## 8. Risk / Rollback Analysis
   575→
   576→### 8.1 Risk level: **MEDIUM**
   577→
   578→**Justification:**
   579→
   580→- **MEDIUM, not LOW**, because C1 modifies the **shared idempotency library** (`src/lib/idempotency.ts`) that both critical paths (`/api/orders` + `/api/payments`) depend on. A bug in the hash computation or comparison logic could break ALL idempotent writes, not just one route. Blast radius = Order creation + Payment capture = the two most critical paths in the system.
   581→- **MEDIUM, not HIGH**, because:
   582→  - The feature flag (`requestHashEnforcement`, default OFF) provides a kill-switch. Even after deploy, the new code path is dormant. A bug in the hash-computation code would NOT affect production behavior until the flag is flipped ON.
   583→  - The schema migration is Class-2 expand-migrate-contract (additive nullable column). Old code (pre-3c) reads the new column as `null` and continues to work. No breaking change to existing rows.
   584→  - The null-hash short-circuit provides backward compatibility for pre-3c records. Even with the flag ON, old records continue to behave per Option A.
   585→  - The 3a/3b evidence (11 scenarios, S5 PASS / CLOSED) remains valid for the flag-OFF path. The flag-OFF path is byte-identical to 3b behavior. So even if 3c introduces a bug, the 3a/3b evidence proves the flag-OFF path is safe.
   586→
   587→### 8.2 Rollback plan
   588→
   589→| Implementation scope | Rollback procedure | Time | Safe by default? |
   590→|----------------------|---------------------|------|------------------|
   591→| Schema only (add column) | `ALTER TABLE IdempotencyKey DROP COLUMN requestHash` (safe — column is nullable + no indexes depend on it). | <5 min | YES |
   592→| Code only (idempotency.ts + deployment.ts + routes) | Git revert. No DB rollback needed (column remains nullable; old code reads `null` for all new rows, which triggers the null-hash short-circuit). | <10 min | YES |
   593→| Feature flag flip (OFF → ON) | Flip flag back to OFF (via Vercel env var or deployment.ts `getFlag` default). No code deploy needed if flag is read at runtime. | <1 min | YES |
   594→| Full 3c deploy (schema + code + flag ON) | (1) Flip flag to OFF. (2) Git revert code. (3) `DROP COLUMN requestHash`. All three steps are independent and safe. | <15 min | YES |
