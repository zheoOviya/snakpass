    53→

    55→
    56→- faster
    57→- cheaper
    58→- social
    59→- rewarding

   581→
   582→The pickup QR is a core product feature.
   583→
   584→Flow:
   585→
   586→```text
   587→Order READY
   588→     ↓
   589→Generate pickup credential
   590→     ↓

   592→     ↓

   603→

   923→# 27. PAYMENT ARCHITECTURE
   924→
   925→Payment must be modeled as a state machine.
   926→
   927→Do not do:
   928→
   929→```text
   930→create order
   931→→ call gateway
   932→→ assume success
   933→```
   934→
   935→Instead:
   936→
   937→```text
   938→Create order
   939→→ generate internal idempotency key
   940→→ create payment intent/order
   941→→ gateway interaction
   942→→ verify callback/webhook
   943→→ persist authoritative payment state
   944→→ fulfilment proceeds according to policy
   945→```
   946→
   947→All external gateway calls must have explicit retry/idempotency strategy.
   948→
   949→Existing Gateway E1-E9 governance remains mandatory.
